# 201. 관리자의 강의실 Analytics 프로젝트 접근

## 무엇을 했나요?

운영 강의실을 관리하는 canonical 관리자만 강의실의 이미 연결된 Analytics 프로젝트를 한 번에 조회할 수 있도록 접근 권한 재조정 API를 추가했습니다.

## 왜 필요한가요?

학생별 서비스 지표를 수업 운영자가 확인하려면 각 프로젝트를 수동으로 공유해야 했습니다. 이 과정은 누락되기 쉽고, 잘못 구현하면 다른 강의실이나 회사의 프로젝트까지 열릴 수 있습니다.

## 어떻게 안전하게 만들었나요?

- 로그인 토큰의 값만 믿지 않고 DB의 승인 상태와 admin role을 다시 확인합니다.
- 지정된 canonical 관리자와 활성 강의실 범위만 허용합니다.
- 이메일은 허용 대상 확인에만 쓰고, 실제 Rybbit 계정 연결은 기존 OAuth `sub`를 사용합니다.
- 회사별 organization 경계를 유지한 채 연결 완료된 사이트만 재조정합니다.
- 일반 관리자와 학생은 기존 자기 회사 범위 그대로 유지됩니다.

## 검증

canonical 관리자 성공, 일반 관리자 거부, 강의실 범위, stable OAuth subject 전달을 integration test로 확인했습니다.

## 사용한 프롬프트

관리자 canonical 계정에 운영 강의실 전체 Analytics 프로젝트 조회 권한을 최소 범위로 구현하고 Stage와 Production에서 검증해 달라는 요청.

## 배운 점

관리자 기능도 전역 bypass보다 대상 identity와 tenant 범위를 명시적으로 검증하는 편이 더 안전합니다.
