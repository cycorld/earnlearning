# 전체 테스트의 컴파일 계약 복구

## 무엇을 했나요?

백엔드 전체 테스트가 컴파일 단계에서 멈추던 두 테스트 보조 코드를 현재 프로덕션 인터페이스와 맞췄습니다.

## 왜 필요한가요?

인터페이스는 구현체뿐 아니라 테스트에서 사용하는 가짜 객체(fake)에도 같은 계약을 요구합니다. 새 메서드나 인자가 추가될 때 fake와 테스트 호출도 함께 갱신하지 않으면 실제 테스트 실행 전에 컴파일이 실패합니다.

## 어떻게 만들었나요?

Go 1.24 컨테이너에서 `sqlite_fts5` 빌드 태그를 사용해 실패를 먼저 재현했습니다. 그 뒤 위키 저장소 fake에 문서 조회 메서드를 추가하고, 상장사 조회 테스트에는 테스트 데이터가 속한 강의실 ID를 명시했습니다. 검증 조건은 삭제하거나 완화하지 않았습니다.

## 사용한 프롬프트

> 최신 main의 백엔드 전체 테스트 컴파일 실패를 TDD 방식으로 수정하라

## 배운 점

테스트 fake도 프로덕션 인터페이스의 사용자입니다. 전체 패키지 테스트를 정기적으로 컴파일하면 개별 패키지 테스트만으로 놓치기 쉬운 계약 불일치를 빠르게 찾을 수 있습니다.
