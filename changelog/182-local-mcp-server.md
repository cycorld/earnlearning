# 로컬 MCP 서버: AI 도구에 안전한 읽기 창구 만들기

## 무엇을 했나요?

EarnLearning의 기존 읽기 전용 API를 MCP(Model Context Protocol) 클라이언트에서 호출할 수 있는 로컬 stdio 서버를 만들었습니다. MCP는 AI 도구와 외부 기능이 서로 어떤 도구를 제공하고 어떻게 호출할지 합의하는 규격입니다.

서버는 `initialize`, `tools/list`, `tools/call` JSON-RPC 요청을 처리하며 다음 API만 노출합니다.

- `/api/health`: 서버 상태
- `/api/auth/me`: 현재 사용자 프로필
- `/api/grants`: 정부과제 목록
- `/api/companies`: 기업 목록
- `/api/posts`: 클래스룸 게시물 목록

## 왜 필요한가요?

AI 도구에 웹 서비스 전체 권한을 주는 대신, 이미 존재하는 읽기 API 중 필요한 경로만 작은 도구로 공개하면 권한과 위험을 줄일 수 있습니다. 특히 실제 학생 데이터가 있는 서비스에서는 기본값이 편리함보다 안전함을 우선해야 합니다.

## 어떻게 안전하게 만들었나요?

- API 주소와 bearer token이 없으면 실행하지 않는 **실패 폐쇄** 방식을 사용했습니다.
- 기본적으로 `localhost`와 loopback 주소만 허용합니다. 원격 API는 `EARNLEARNING_MCP_ALLOW_REMOTE=true`라는 명시적 선택이 있어야 합니다.
- 프로덕션 주소나 토큰을 코드에 넣지 않았습니다.
- 목록의 `limit`은 최대 50으로 제한하고 필수 ID, 페이지, 문자열 길이를 검증합니다.
- HTTP 응답 크기와 시간도 제한합니다.
- 토큰은 요청 헤더에만 사용하며 오류와 로그에는 포함하지 않습니다.
- `httptest`로 인증 헤더, 입력 검증, 원격 URL 거부, 도구 목록과 호출, 토큰 비노출을 테스트했습니다.

## 사용한 프롬프트

“secure local stdio MCP server MVP를 구현하고, 기존 읽기 API만 사용하며 localhost 기본 제한·토큰 비노출·페이지 제한·구조화 오류와 테스트를 추가해 달라”는 요구를 바탕으로 작업했습니다.

## 배운 점

안전한 연동의 핵심은 무엇을 더 많이 연결하느냐가 아니라, **기본적으로 연결하지 않고 필요한 범위만 명시적으로 여는 것**입니다. 또한 API 경로와 응답을 추측하지 않고 실제 라우터와 핸들러를 확인하면 연동 코드와 서비스 계약이 어긋나는 일을 줄일 수 있습니다.
